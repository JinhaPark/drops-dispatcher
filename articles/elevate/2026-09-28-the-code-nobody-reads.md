# [The Code Nobody Reads](https://addyo.substack.com/p/the-code-nobody-reads)

2026.09.28 · Addy Osmani · Elevate

AI가 작성하는 코드의 양이 급증하면서 모든 변경 사항을 사람이 한 줄씩 읽어 검토하는 방식은 지속하기 어려워졌습니다. Addy Osmani는 코드 리뷰가 사라지는 것이 아니라 그 역할과 책임이 바뀐다고 설명합니다. 과거에는 개발자가 직접 구현을 읽고 문제를 발견하는 과정이 중심이었지만, 이제는 에이전트가 먼저 결함을 탐색하고 검증 증거를 제시하며 사람이 위험과 영향 범위를 판단하는 방식이 중요해졌습니다. 자동화된 검토를 통과했다고 해서 변경의 목적이나 제품 요구사항까지 충족했다고 보장되는 것은 아닙니다. 특히 인증, 결제, 권한과 같이 실패의 파급효과가 큰 영역에는 여전히 신중한 사람의 검토가 필요합니다.

저자는 여러 에이전트가 먼저 코드를 분석하고 발견한 문제를 심각도에 따라 정리하는 검토 구조를 소개합니다. 상대적으로 영향이 작은 변경은 자동 검증 결과를 바탕으로 간결하게 승인할 수 있지만, 핵심 업무 흐름은 담당자가 충분히 이해하고 책임을 져야 합니다. 테스트 결과, 실제 동작, 성능과 운영 지표는 단순한 코드 차이보다 중요한 판단 자료가 될 수 있습니다. 그러나 테스트 자체가 잘못 설계되었다면 정상이라는 신호도 믿기 어렵습니다. 따라서 무엇을 검증했고 무엇은 검증하지 못했는지 명시하는 것이 중요합니다.

코드 리뷰에는 오류 발견 이외의 역할도 있었습니다. 주니어 개발자는 리뷰 과정에서 선임의 설계 판단과 팀의 관례를 배웠습니다. 사람이 매번 같은 조언을 반복하지 않게 되면 그 지식은 스킬, 테스트, 정적 분석 규칙, 저장소 지침에 옮겨져야 합니다. 단순히 에이전트가 많은 코드를 처리하도록 만드는 것보다 팀의 판단 기준을 누적하고 재사용하는 체계가 중요합니다. 또한 개발자가 자동화 결과를 이해할 수 없다면 코드가 늘어날수록 이해 부채가 쌓입니다. 저자의 결론은 모든 코드를 직접 읽지 않더라도 무엇을 배포할지 결정하는 사람의 책임은 남아 있어야 한다는 것입니다.
