# [Speech-to-Code: Vibe Coding with Voice](https://addyo.substack.com/p/speech-to-code-vibe-coding-with-voice)

2025.02.28 · Addy Osmani · Elevate

애디 오스마니는 음성 입력과 AI 코딩 도구를 결합하면 생각을 구현으로 옮기는 과정이 달라진다고 설명합니다. 여기서 음성 코딩은 프로그램의 구두점까지 읽어 주는 작업이 아닙니다. 개발자가 원하는 동작이나 수정 방향을 말하면 음성 인식기가 이를 텍스트로 바꾸고, 코딩 도구가 그 요청을 바탕으로 코드를 제안합니다. 저자는 직접 사용하면서 입력 부담을 줄였다고 이야기하지만, 개인의 경험을 모든 개발자의 생산성 향상을 보장하는 수치로 받아들일 필요는 없습니다.

글은 SuperWhisper 같은 음성 인식 도구를 편집기와 연결하고, 자주 틀리는 기술 용어를 보정하는 방법을 소개합니다. 조용한 환경에서 분명하게 말하고 복잡한 요청은 짧게 나누면 수정하기 쉽습니다. 잘못 인식한 내용을 곧바로 고치며, 세밀한 편집에는 키보드와 마우스를 함께 사용합니다. 손의 반복 입력을 줄이는 장점도 있지만, 개발자는 생성된 코드의 의미와 테스트 결과를 계속 확인해야 합니다. 말하기가 입력 경로를 바꾸어도 프로그램의 정확성을 책임지는 과정까지 대신하지는 않습니다.

실무에서는 말을 빠르게 하는 능력보다 요청을 구분하는 방식이 효과를 좌우할 수 있습니다. 예를 들어 검색 화면을 고칠 때 색상, 필터 동작, 오류 처리까지 한꺼번에 설명하면 무엇을 수정했는지 확인하기 어렵습니다. 먼저 검색 조건을 유지하는 동작을 요청하고, 결과를 살핀 다음 표시 방식으로 넘어가면 변경의 원인을 추적하기 쉽습니다. 이때 음성으로 남긴 문장은 동료에게 작업을 설명하는 작은 명세 역할도 합니다. 다만 말로 전달한 의도가 코드에 정확히 반영되었는지는 별도로 비교해야 합니다.

도입 효과를 확인하려면 같은 유형의 작업에서 입력 시간뿐 아니라 오인식 수정과 결과 검토에 걸린 시간을 함께 기록할 수 있습니다. 처음 말을 시작하기 쉬운지, 긴 요청을 다시 정리해야 하는지도 살펴볼 항목입니다. 주변 사람과 공간을 공유한다면 소리 내어 설명하는 방식이 업무 환경에 맞는지도 판단해야 합니다. 결국 음성은 모든 입력을 대체해야 가치가 생기는 기능이 아닙니다. 설계를 풀어 설명할 때와 정확한 기호를 고칠 때 서로 다른 입력 방식을 선택하면, 사용자는 자신의 사고 흐름과 작업 조건에 맞는 조합을 만들 수 있습니다.
