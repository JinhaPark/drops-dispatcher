# [The AI-Native Software Engineer](https://addyo.substack.com/p/the-ai-native-software-engineer)

2025.07.01 · Addy Osmani · Elevate

Addy Osmani가 말하는 AI 네이티브 소프트웨어 엔지니어는 AI를 일상적인 문제 해결 과정에 통합하는 개발자입니다. 코드를 빨리 작성하는 데서 멈추지 않고 조사, 계획, 문서화와 운영까지 활용 범위를 넓힙니다. 그만큼 개발자의 역할도 작업을 직접 수행하는 일에서 의도를 명확히 전달하고 결과를 검증하는 일로 이동합니다. 저자는 큰 생산성 향상을 기대하지만, 효과는 작업의 복잡성과 감독 방식에 달려 있다고 설명합니다.

도입은 이해하고 검토할 수 있는 작은 작업부터 시작합니다. 관련 코드와 목표, 출력 형식을 제공하고 결과에서 발견한 오류를 다음 요청에 반영합니다. 글은 기존 코드를 유지하는 편집기 기반 도구, 새 프로젝트의 초안을 만드는 시제품 도구, 별도 환경에서 작업하는 에이전트를 구분합니다. 중요한 선택 기준은 각 개발 단계에서 필요한 역할입니다. 생성한 초기 결과에는 업무 규칙과 품질을 다듬는 추가 작업이 남는다고 강조합니다.

AI 활용에는 팀의 운영 방식도 따라야 합니다. 요구사항과 실행 계획을 기록하고, 코드 검토와 테스트로 변경을 확인하며, 외부 서비스에 전달할 수 있는 정보를 구분합니다. 저자는 성공 사례뿐 아니라 실패와 수정 경험을 공유하고 기본 역량을 계속 학습하자고 권합니다. 도구에 맡길 범위를 넓히더라도 결과의 정확성과 유지보수 책임은 개발자에게 남습니다. 글의 제품 소개는 발행 당시의 도구 환경을 설명하는 자료입니다.

이 관점을 실무로 옮기는 편집상의 예시는 팀에서 자주 반복되는 인수인계 문서를 개선하는 일입니다. 매번 새 기능을 자동 생성하려 하기보다, 최근 변경 사항을 정리하는 초안을 AI에 맡기고 담당자가 누락된 운영 조건을 보완해 볼 수 있습니다. 이후 새로 온 동료가 그 문서만으로 개발 환경을 준비할 수 있는지 확인합니다. 이 사례는 원문에 없는 적용 제안입니다. 문서가 길어졌는지보다 질문과 재작업이 줄었는지를 관찰하면 도움이 됩니다. 효과가 있다면 비슷한 업무로 범위를 넓히고, 효과가 작다면 자료의 구조나 검토 절차를 먼저 고칩니다. 이러한 접근은 특정 제품 사용 자체를 목표로 삼지 않고 팀이 반복해서 겪는 불편을 출발점으로 삼는 방식입니다.
