# [Agentic Primitives: Six Levers of Agent Sovereignty](https://www.linkedin.com/pulse/agentic-primitives-six-levers-agent-sovereignty-andr%C3%A9-lindenberg-vkn3f)

Artificial Engineering · Edition 53 · 2026-05-02 · André Lindenberg

같은 언어 모델도 주변 실행 환경에 따라 성능과 위험이 크게 달라집니다. André Lindenberg는 에이전트 하네스, 즉 모델을 실제 작업 시스템으로 만드는 실행 기반을 여섯 기능으로 나누는 연구를 소개합니다. 도구 형식이나 문맥 관리만 바꿔도 평가 결과가 달라진 사례가 출발점입니다. 저자는 이를 근거로 조직이 모델 선택에만 집중해서는 에이전트를 통제하기 어렵다고 주장합니다. 무엇을 실행하고 어떤 정보를 기억하며 어디서 멈추는지가 이미 모델 호출 바깥에서 결정되기 때문입니다. 모델의 지능과 시스템의 신뢰성은 구분해서 살펴야 합니다.

여섯 기능은 실행 반복문, 도구 목록, 문맥 관리자, 상태 저장소, 생명주기 훅, 평가 인터페이스입니다. 실행 반복문은 종료와 복구를 책임지고 도구 목록은 가능한 행동과 입력 형식을 정합니다. 문맥 관리자는 매 순간 모델에 제공할 정보를 고르고, 상태 저장소는 세션이 끝나도 남을 내용을 관리합니다. 훅은 호출 전후에 인증과 정책 검사를 끼워 넣는 지점이며, 평가 인터페이스는 실행 경로를 외부 검토에 필요한 형태로 기록합니다. 각 기능에는 끝없는 실행, 잘못된 도구 사용, 문맥 초과처럼 대응해야 할 구체적인 실패가 있습니다.

이 구분은 보안과 감사의 책임을 찾는 데도 유용합니다. 개인정보가 문맥에 들어가는 경로와 장기 기억에 남는 경로를 따로 검토하고, 도구 권한과 실행 기록도 별도로 확인할 수 있습니다. 특히 오염된 기억이 다음 세션에 영향을 주는 문제는 저장 단계의 검증 없이는 오래 지속될 수 있습니다. 글은 최소 도구만 제공하는 Pi와 더 넓은 실행 기능을 갖춘 OpenClaw를 비교합니다. 목적은 특정 제품의 우월성을 선언하는 데 있지 않습니다. 조직이 자신에게 필요한 기능을 이해하고 직접 점검할 수 있는지가 중요합니다.

컨테이너로 실행을 격리하거나 모델에 안전한 응답을 학습시키는 일도 이러한 책임을 모두 대신하지는 못합니다. 저자는 실행 환경의 취약점과 도구 사용 제한이 별개의 문제임을 강조합니다. 다만 글에서 인용한 성능 개선과 보안 실험은 특정 구성에서 나온 결과이므로 모든 서비스에 같은 수치가 적용된다고 볼 수는 없습니다. 팀은 여섯 기능을 기준으로 권한과 데이터 흐름, 실패 복구, 검증 기록의 담당자를 정할 수 있습니다. 에이전트에 대한 통제권은 기능의 개수가 아니라 실제 운영 계약을 얼마나 명확히 이해하고 관리하는지에서 드러납니다.
