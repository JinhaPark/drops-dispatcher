# [Battle Drones—a vibe coded RTS with audio-based multiplayer](https://simonwillison.net/2026/Oct/20/battledrones/)

2026-10-20 · Simon Willison

Simon Willison은 코딩 에이전트와 대화하는 방식으로 모바일에서도 실행되는 실시간 전략게임 ‘Battle Drones’를 만들었습니다. 1990년대의 Command & Conquer에서 출발한 구상이지만, 완성된 결과보다 제작 과정에 더 흥미로운 이야기가 있습니다. 저자는 게임 개발 경험이 풍부하지 않은 상태에서 Claude Code에 기능 구현과 개선을 맡겼습니다. 약 12차례의 큰 개편과 코딩 에이전트가 작성한 321개 커밋을 거치며 건물 건설, 유닛 지휘, 적 인공지능, 여러 지도, 캠페인, 자동 생성 지도까지 갖춘 브라우저 게임으로 발전했습니다. 별도의 설치가 필요 없는 정적 웹페이지라는 점도 이 실험의 중요한 조건입니다.

첫 번째 시제품은 명령을 내리고 전투를 벌일 수 있었지만 정작 재미는 부족했습니다. 저자가 Claude에 게임을 훨씬 재미있게 만들어 달라고 요청하자, 에이전트는 전투가 늘어지거나 일방적으로 끝나는 문제를 줄이기 위해 전략 선택지, 역전 기회, 목표 지점, 보상과 시각·음향 효과 등을 도입했습니다. 글에서 소개한 내부 실험에서는 인공지능끼리 벌인 대량의 모의 경기를 분석해 균형을 조정했습니다. 이는 모델이 코드를 생성하는 데 그치지 않고, 실행 결과를 측정해 다시 설계하는 반복적인 개발 절차를 수행할 수 있음을 보여줍니다. 다만 게임의 재미를 사람이 최종적으로 평가해야 한다는 점은 여전히 남습니다.

기술적으로 가장 독특한 부분은 두 기기 사이의 멀티플레이입니다. 일반적으로는 서버나 네트워크 연결을 사용하지만, 이 프로젝트에서는 스피커와 마이크로 정보를 주고받는 음향 통신을 이용했습니다. 앞서 제작한 간단한 탁구게임 실험을 에이전트에 참고하도록 하고, 통신 가능한 데이터량을 측정하는 도구를 만든 다음 게임 상태를 동기화했습니다. 서로 다른 브라우저가 수학 함수를 계산할 때 생기는 미세한 차이까지 게임 동기화를 깨뜨릴 수 있어, 일부 계산을 직접 구현해야 했다는 사례도 소개합니다. 서버 운영 부담을 피하려는 선택이 새로운 기술적 제약을 낳은 셈입니다.

이 글은 ‘자연어로 프로그램을 만들 수 있다’는 선언보다 구체적인 실무적 질문을 던집니다. 에이전트가 시뮬레이션과 진단 도구, 재현 가능한 기록을 직접 만들도록 유도하면 복잡한 과제를 더 잘 다룰 수 있을까요? 실제 프로젝트에서는 변경 이력, 사용자 경험의 확인, 서로 다른 기기에서의 동작 테스트를 분리해 살펴봐야 합니다. 저자는 만들어진 결과가 기대 이상이었다고 평가하면서도, 아직 충분히 시험하지 못한 기능이 있다고 밝힙니다. 생산성을 크게 높이는 자동화와 결과물에 대한 사람의 검증 책임이 함께 커진다는 점에서 코딩 에이전트의 현재를 잘 보여주는 실험입니다.
